# TrPTools security, performance and usability audit

Date: October 3, 2026 (America/Phoenix). Scope: the three applications under `Project`, shared Docker configuration, dependency lockfiles, and the relevant reference behavior in `AGENTS.md`. Legacy examples were not edited. Fixes are included in release v3.4.1. Publication and production deployment are separate steps.

## Findings and fixes

All 19 findings below have code fixes. Priorities indicate impact before the fix: P1 is a security boundary or shared-service stability issue; P2 is a bounded security, reliability, performance or usability defect.

| ID | Priority | Finding | Fix and evidence |
| --- | --- | --- | --- |
| SEC-01 | P1 | Most authenticated endpoints ignored API-key scopes. A read-only key could mutate resources or create broader keys; the realtime endpoint also missed its scope check. | Central fail-closed namespace/method policy in `authPlugin` and `apiKeyPolicy`. Account/key/elevation operations require browser sessions. Pure scope matrix and real HTTP read/write/key-management tests pass. Existing group grants remain required. |
| SEC-02 | P1 | Individual depot reads missed private/hidden parent groups. Direct route reads missed parent moderation and archive checks; anonymous schedule reads missed parent moderation. | Shared publication predicates for route/depot reads and the missing schedule gate. Test matrix covers publication, archive and moderation; HTTP fixture checks parent privacy/hidden state and public reads. |
| SEC-03 | P1 | Open dispatch streams retained access after session/key revocation, suspension or permission changes. | Re-resolve credentials and dispatch permission at each 15-second heartbeat; close and release presence on refusal or failed authorization check. Native/edge Redis integration tests verify closure and actual presence cleanup. Membership demotions still follow the established 60-second cache. |
| SEC-04 | P1 | Direct Bun requests could choose a rate-limit bucket by spoofing forwarded/Cloudflare IP headers. | Socket peer address by default; forwarded headers require explicit trusted-proxy configuration. Cloudflare keeps its trusted edge behavior. Spoofing and proxy opt-in regression tests pass. |
| SEC-05 | P1 | Production accepted a publicly known development encryption key; shared Compose exposed Postgres/Valkey on all interfaces. | Fail startup for the default encryption key, require an explicit Compose key, and bind database/cache ports to loopback. Subprocess configuration regression passes. Docker runtime verification is unavailable on this machine. |
| SEC-06 | P1/P2 | Dependency audits returned 11 backend, 18 frontend and 13 bot advisory entries, including high-severity advisories. Counts overlap across apps. | Patch devalue, both affected undici major lines, cookie and esbuild. Parent-scoped overrides avoid upgrading Discord's undici across majors. Final `bun audit`: zero known advisories in every app. Frozen lockfile installs and application/Worker builds pass. |
| SEC-07 | P2 | Policy redirect files accepted root paths containing backslashes/control characters, HTTP destinations, and URLs with embedded credentials. | Reject ambiguous root paths; permit credential-free HTTPS external links. Regression vectors cover backslash, protocol-relative, control-character and credential escapes. |
| SEC-08 | P2 | An in-flight report could overwrite a moderator's newly approved state with HIDDEN. | Auto-hide update atomically excludes APPROVED rows; report response reflects whether hiding occurred. Approved-content fixture passes. |
| PERF-01 | P1 | Manager-authored dispatch regexes used native backtracking on every vehicle; `(a+)+$` can block the shared server on a nonmatching name. | Portable RE2JS linear-time matching, with a bounded compiled-pattern cache. Exact-name priority and normal pattern semantics pass existing solver tests; pathological matching regression passes. |
| PERF-02 | P1 | Recurrence parsing accepted sub-hourly rules and large time expansions, allowing millions of iterations during public listings/scheduler work. | Single-rule validation, minimum hourly frequency, positive interval, count cap of 10,000 and time-field expansion cap of 24. Simple hourly series now jump directly to the requested window. Old daily/weekly/monthly/hourly correctness and abusive-rule rejection tests pass. |
| PERF-03 | P2 | Bot and storage fetches lacked deadlines; redirects could forward service credentials or move signed storage requests unexpectedly. | 15-second request deadlines, 30 seconds for bot manifest images, and redirect refusal. Bot transport regression and fake signed-storage integration pass. |
| PERF-04 | P2 | Gateway automation repeatedly fetched every guild's full configuration, and intervals could overlap slow preceding runs. `/status` serialized independent reads. | Lightweight board index, full reads only for tracked/due boards, in-flight guards for scheduler/board ticks, and parallel status reads. Gateway polling and existing board/Worker regressions pass. |
| PERF-05 | P2 | A 200-report moderation page could issue approximately 601 queries, with hundreds in parallel. | Batch target snapshots, group contexts and galleries: at most seven select calls. Integration verifies bounded reads and intact route/image snapshots. |
| REL-01 | P1 | Separate count/check/insert writes let concurrent sign-ups exceed capacity or reserve different slots for the same linked identity. Discord moves deleted the old reservation before a fallible insert. | Postgres advisory-lock trigger plus API conflict mapping; Discord moves update one row. Twelve-way DB/HTTP races, linked web/Discord duplication and failed-move preservation pass. Migration applied successfully to a disposable database. |
| REL-02 | P2 | Failed media inserts/icon linkage could leave uploaded objects or rows orphaned. Invalid media IDs and a missing shift owner could reach database queries. | Cleanup on insert/link failure, UUID validation and explicit missing-owner refusal. Fake object-storage and forced database-failure fixture confirms cleanup; failures preserve the existing owner link. |
| UX-01 | P2 | Shared fields displayed labels/help/errors without programmatic association. The time-zone input and mobile account menu had no accessible name; dialogs had no named heading relationship. | Shared field context supplies labels, descriptions and invalid state to input/textarea/select/custom select/color/translatable controls; explicit time-zone/account labels and dialog heading IDs. Browser role/error/keyboard assertions pass. |
| UX-02 | P2 | Gallery lightboxes used a generic backdrop without native focus containment, Escape closing or focus restoration. Long gallery captions could widen grid cells. | Reuse the native-dialog Modal and constrain grid cells. Browser verifies the modal, background focus protection, Escape and return to the opening thumbnail. |
| UX-03 | P2 | Settings/logout handlers awaited Eden requests but ignored returned `error`, reporting success or navigating after a failed save/logout. | Check API error results, retain the language choice on failed synchronization, and avoid contradictory success toasts. Browser injects an account-preference 503 and confirms visible failure feedback. |
| UX-04 | P2 | A 500-vehicle import could submit over 200 owner IDs to an endpoint capped at 200. Failed IDs were marked permanently resolved. | Deduplicate and split requests into 200/200/100; retry failures after 30 seconds and retain successful/missing results. Browser verifies batch sizes, no immediate retry storm and all 500 profiles after recovery. |

## Review coverage

Reviewed authentication/session and admin-mode boundaries, API keys, group grants and public visibility, OAuth/callback handling, rate limiting, moderation, media/storage, sign-up identity/concurrency, recurrence expansion, dispatch solver/state/SSE, bot API/automation, frontend forms/settings/navigation/dialogs, caching and responsive layouts. Existing tests also exercise permission presets, owner pinning, linked identities, eligibility, notification endpoints, signed Discord interactions, worker queues, Redis batching and public/personalized response caching.

The audit uses local fixtures and code review. It does not certify the deployed infrastructure or prove the absence of every vulnerability. Existing public object-storage URLs remain public by design; visibility checks protect pages and API metadata, rather than converting the bucket into private file storage.

## Validation

- Backend: typecheck; 205 source tests plus 11 controller/dashboard tests; Bun build; Worker dry-run build and local workerd smoke.
- Dispatch: 19 integration tests each with native Redis and the edge client; targeted final revocation tests on both. At simulated 150 ms Redis RTT, 50-vehicle imports/solves stay near 0.62 seconds of service time, using four trips each; 500-vehicle cases remain bounded.
- Isolated Postgres/Redis fixture: scope enforcement and private cache headers, route/depot privacy, reservation races and HTTP 409 responses, linked identities, failed move preservation, failed media insert/link cleanup and batched moderation snapshots.
- Frontend: check reports zero errors/warnings; 26 tests; Cloudflare and Node builds; Worker dry-run bundle. Disabled only Rolldown's plugin-timing heuristic, which flagged normal SvelteKit compilation hooks; other build checks remain enabled. Node adapter may print an informational empty env chunk message.
- Bot: typecheck; 77 tests; Worker dry-run build and workerd smoke accepting a valid signed PING and rejecting a forgery without sending Discord messages.
- Browser: home, appearance, solo dispatch, groups and shifts at 1440/768/375/320 px, with no document horizontal overflow; shared-field accessibility/error descriptions, custom-select keyboard selection, image dialog behavior, simulated API failure feedback and 500-profile resolution/retry. Temporary browser harness removed from production routes. Screenshot: `trptools-frontend/output/playwright/audit-mobile.png`.
- Final dependency audits report zero known vulnerabilities in all three lockfiles. Legacy reference trees and production/provider data were not changed.

Docker's daemon was unavailable, so the full Compose build/start and live Garage integration were not run. Actual Roblox/Discord/OAuth behavior and production load were not tested; fake/local providers and existing integration tests cover the changed paths. Workerd's smoke tools print the standard local scheduled-event notice.

## Rollout and compatibility

1. Use the corrected version-1 lockfiles from v3.4.3. Frozen installs and Worker build paths were tested with both Cloudflare's default Bun 1.2.15 and the pinned Bun 1.4.2. Wrangler 4.147.0 supplies patched undici without nested overrides; flat cookie/esbuild overrides keep the other security fixes compatible. `BUN_VERSION=1.4.2` is optional for aligning Cloudflare with Docker/CI.
2. Apply backend migration `0036_signup_guards` before serving the new API. Normal Docker API startup runs migrations. Existing commitments are preserved; there is no destructive cleanup of historical duplicates.
3. Keep the current private `ENCRYPTION_KEY`. If an installation used the public development key, re-encrypt its stored credentials before changing that key; blindly replacing it makes existing encrypted values unreadable.
4. Direct Bun deployments should leave `TRUST_PROXY_HEADERS=false`. Enable it only behind a trusted proxy that replaces IP headers, with direct API access blocked.
5. API-key integrations now need their actual read/write scopes. Account features are browser-only. New endpoint namespaces fail closed until deliberately assigned a scope.
6. Recurrence rules must be hourly or slower, with the documented count/time expansion limits. Existing unsupported rules return no occurrences until corrected. Exact vehicle names continue to take precedence; patterns unsupported by RE2 (such as backreferences/lookahead) use the literal fallback and may need rewriting.

Regression instructions live in the backend/frontend READMEs. The local database and Redis fixtures are disposable and explicitly guarded against production URLs.

## Worker build compatibility follow-up

The original security overrides introduced lockfile version 3. Cloudflare Builds
ignored `.bun-version`, selected Bun 1.2.15, and failed its automatic frozen
install. v3.4.2 documented a dashboard prerequisite but did not remove this
repository compatibility defect. The correction in v3.4.3 removes nested overrides,
updates Wrangler to its patched dependency graph, and uses supported flat cookie
and esbuild overrides. Regenerated version-1 lockfiles install unchanged with
both Bun versions; all three dependency audits remain clear.

CI publication and manual Worker deployment now install frozen lockfiles and run
unit tests using Bun 1.2.15 before switching to the pinned runtime. An unsupported
`Bun.JSONC` call in the frontend's standalone-install test was replaced with the
existing TypeScript JSONC parser. Full Worker build/runtime paths passed locally
under Bun 1.2.15, including frontend language-cookie set/delete assertions,
backend workerd health/rate-limit probes and a bot signed-interaction smoke check.
